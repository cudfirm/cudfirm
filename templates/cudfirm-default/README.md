# CUDFIRM Default Template — Adapter 1

This compatibility adapter connects the normalized CUDFIRM CMS contract to the original public frontend without rewriting `js/script.js` or `css/styles.css`.

## Identity and compatibility

- Template ID: `cudfirm-default`
- Template version: `1.4.0`
- Manifest schema: `1.1.0`
- Minimum CMS contract: `1.0.0`
- Supported contract range: `1.x`
- Required CUDFIRM core: `2.0.0`
- Registration entry: `template.registration.js`

The registration file is the only file that registers this adapter. The shared runtime no longer imports or registers a specific template.

The manifest also declares required and optional assets, their ownership boundary, and intended load order. During Adapter 1, the host page still loads those assets; the shared runtime only validates and reports them.

## Adapter-rendered sections

- Home composition at `#tab1`: Hero, featured Portfolio, and featured Services
- About at `#tab20`
- Services at `#tab3`
- Portfolio at `#tab4`
- Testimonials at `#tab9`
- FAQ at `#tab13`
- Contact at `#connect-content`

The mount elements are generated by `js/script.js`. The runtime waits for adapter-managed mounts before compatibility validation and rendering.

## Explicit legacy/shared-core capabilities

The manifest declares these capabilities without replacing their working implementations:

- Navigation and single-page tab routing: `legacy-core`
- Contact and newsletter submission: `legacy-core`
- SEO application and active-tab page resolution: `legacy-core`
- Theme application and custom CSS: `shared-core`
- Maintenance mode: shared CUDFIRM core

This keeps Adapter 1 stable while allowing future adapters to declare their own selectors and renderers.

## Compatibility reporting

`window.CUDFIRM_RUNTIME.getCompatibilityReport()` reports:

- template registration metadata;
- manifest, contract, and core versions;
- route, SEO, theme, and navigation capabilities;
- missing mounts or renderers;
- missing section and list-item fields;
- invalid fallback or manifest settings;
- warnings for optional compatibility gaps.

`window.CUDFIRMTemplateRegistry.list()` lists explicitly registered templates.

## Fallback behavior

Empty normalized arrays keep the legacy fallback markup. A renderer failure is isolated by the shared runtime and does not block unrelated sections.

## Boundaries

The adapter does not query Supabase, authenticate users, submit forms, or implement dashboard/security logic. Shared CMS, form, SEO, theme, and security behavior remains outside the template adapter.
